## 📝 详细步骤

### 第一步：确保代码已推送到 GitHub

```powershell
# 1. 检查 Git 状态
cd d:\community-vote-management
git status

# 2. 提交所有更改
git add .
git commit -m "准备部署到云托管"

# 3. 推送到 GitHub
git push origin main

# 4. 确认推送成功
# 访问 https://github.com/你的用户名/community-vote-management
# 确认代码已更新
```

### 第二步：开通云托管

1. 打开**微信开发者工具**
2. 打开你的小程序项目
3. 点击**"云开发"**按钮
4. 在左侧菜单找到**"云托管"**
5. 如果是首次使用，点击**"开通"**（免费）

### 第三步：创建服务

1. 在云托管页面点击**"新建服务"**
2. 填写服务信息：
   - **服务名称**：`admin-api`
   - **服务备注**：`社区投票管理后台API`
3. 点击**"确定"**

### 第四步：配置环境变量

1. 进入刚创建的服务 `admin-api`
2. 点击**"环境变量"**标签
3. 点击**"新增"**，添加以下变量：

| 变量名           | 值             | 获取方式                |
| ---------------- | -------------- | ----------------------- |
| `TCB_ENV_ID`     | 你的环境 ID    | 云开发 → 设置 → 环境 ID |
| `TCB_SECRET_ID`  | 你的 SecretId  | 云开发 → 设置 →API 密钥 |
| `TCB_SECRET_KEY` | 你的 SecretKey | 云开发 → 设置 →API 密钥 |
| `PORT`           | `3000`         | 固定值                  |
| `NODE_ENV`       | `production`   | 固定值                  |

**重要**：环境变量配置后需要重新部署才生效！

### 第五步：使用 GitHub 部署

1. **点击"新建版本"**

2. **选择部署方式**：在截图中点击 **"Github"** 图标

3. **授权 GitHub**（首次使用）：

   - 点击"授权 GitHub"
   - 会跳转到 GitHub 授权页面
   - 点击"Authorize"确认授权
   - 授权成功后会自动返回

4. **选择代码仓库**：

   - **仓库**：选择 `community-vote-management`
   - **分支**：选择 `main`
   - **触发方式**：手动触发（首次部署）

5. **配置构建参数**：

   **代码路径配置**：

   - **代码目录**：`admin`（重要！因为后端代码在 admin 文件夹）
   - **Dockerfile 路径**：`Dockerfile`（相对于 admin 目录）

   **构建配置**：

   - **构建方式**：Dockerfile
   - **构建目录**：`.`（当前目录）

6. **配置运行参数**：

   **容器配置**：

   - **服务端口**：`3000`
   - **启动命令**：默认（使用 Dockerfile 中的 CMD）

   **资源配置**：

   - **CPU**：`0.25 核`（小型应用够用）
   - **内存**：`0.5 GB`（小型应用够用）
   - **最小实例数**：`1`（保证服务不中断）
   - **最大实例数**：`2`（自动扩容上限）

7. **高级配置**（可选）：

   **健康检查**：

   - **检查路径**：`/api/health`
   - **检查端口**：`3000`
   - **初始延迟**：`10` 秒
   - **检查间隔**：`30` 秒
   - **超时时间**：`3` 秒
   - **健康阈值**：`3` 次
   - **不健康阈值**：`3` 次

8. **版本信息**：

   - **版本名称**：`v1.0.0`
   - **版本备注**：`初始版本 - GitHub自动部署`

9. **点击"开始部署"**

### 第六步：等待部署完成

部署过程大约 **3-5 分钟**，包括：

1. ✅ 从 GitHub 拉取代码
2. ✅ 读取 admin 目录
3. ✅ 构建 Docker 镜像
4. ✅ 推送镜像到容器仓库
5. ✅ 启动容器实例
6. ✅ 健康检查通过

**查看部署进度**：

- 在版本详情可以看到实时日志
- 如果出错，日志会显示详细错误信息

### 第七步：验证部署

1. **检查服务状态**：

   - 服务状态：运行中（绿色）
   - 实例数量：≥ 1

2. **获取访问地址**：

   - 在服务详情页找到"访问配置"
   - 复制"默认域名"：
     ```
     https://admin-api-xxx.service.tcloudbase.com
     ```

3. **测试 API**：

   打开浏览器或使用 curl 测试：

   ```bash
   # 测试健康检查
   curl https://admin-api-xxx.service.tcloudbase.com/api/health

   # 应该返回：
   # {"status":"ok","timestamp":"2026-01-01T12:00:00.000Z","uptime":123}
   ```

## 🔄 配置自动部署（推荐）

部署成功后，可以启用**自动部署**功能：

1. 在服务设置中找到"触发方式"
2. 启用"代码推送时自动部署"
3. 以后每次 `git push` 到 main 分支，云托管会自动部署

**工作流程**：

```
本地修改代码 → git commit → git push → 自动触发部署 → 更新完成
```

## 🎯 其他部署方式

### 方式 B：使用 Gitee（国内更快）

如果 GitHub 访问较慢，可以使用 Gitee：

1. **同步代码到 Gitee**：

   ```bash
   git remote add gitee https://gitee.com/你的用户名/community-vote-management.git
   git push gitee main
   ```

2. **在云托管选择"Gitee"部署方式**
3. **其他步骤与 GitHub 完全相同**

### 方式 C：使用命令行（适合开发者）

```bash
# 1. 安装 CloudBase CLI
npm install -g @cloudbase/cli

# 2. 登录
tcb login

# 3. 进入项目目录
cd d:\community-vote-management\admin

# 4. 初始化云托管
tcb run init
# 根据提示填写：
# - 环境：选择你的云开发环境
# - 服务名：admin-api
# - 使用 Dockerfile：是

# 5. 部署
tcb run deploy --service admin-api

# 6. 查看部署状态
tcb run service:list
```

如果你点击"Express 模板"：

- 会创建一个新的 Express 项目
- 需要手动上传你的代码文件
- **不推荐用于生产环境**

## ⚙️ 扩缩容配置

### 自动扩缩容规则

**扩容触发**（满足任一条件）：

- CPU 使用率 > 70%
- 内存使用率 > 70%
- 并发请求数 > 单实例承载上限

**缩容触发**（同时满足）：

- CPU 使用率 < 30% 持续 5 分钟
- 内存使用率 < 30% 持续 5 分钟
- 实例数 > 最小实例数

### 手动调整资源

如果资源不够：

1. 进入服务 → 版本管理
2. 编辑当前版本
3. 修改配置：
   - CPU：0.25 → 0.5 核
   - 内存：0.5 → 1 GB
   - 最大实例数：2 → 5
4. 保存并重新部署

## ❓ 常见问题

### Q1：找不到 admin 目录下的 Dockerfile？

**原因**：代码目录配置错误

**解决**：

1. 确认 GitHub 仓库中 admin 目录下有 Dockerfile
2. 在部署配置中，代码目录填写：`admin`
3. Dockerfile 路径填写：`Dockerfile`（相对于 admin 目录）

### Q2：部署失败，提示"构建镜像失败"？

**解决步骤**：

1. 查看详细构建日志
2. 确认 package.json 中所有依赖都正确
3. 确认 Dockerfile 语法正确
4. 如果是网络问题，重试部署

### Q3：部署成功但访问返回 502？

**可能原因**：

- 应用启动失败
- 端口配置错误
- 环境变量未配置

**解决**：

1. 查看容器日志
2. 确认环境变量已配置
3. 确认端口为 3000
4. 检查应用启动日志

### Q4：环境变量修改后不生效？

**原因**：环境变量需要重新部署才生效

**解决**：

1. 修改环境变量
2. 保存
3. 新建版本重新部署
4. 或在现有版本中重启实例

### Q5：如何回滚到上一个版本？

**步骤**：

1. 进入版本管理
2. 找到历史版本
3. 点击"切换流量"
4. 将流量切换到该版本（0-100%）
5. 支持灰度发布（逐步切换）
